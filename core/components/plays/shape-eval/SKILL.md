# shape-eval

A person names a business intent whose plan `/shape-plan` made. /shape-eval writes, for each
slice the plan holds, the slice's **one eval**, in Gherkin, in the slice's evals folder
(`.garura/project/plans/<intent-issue>/evals/<slug>/`, beside the hidden file): a scenario for
each goal and each expectation of the slice's stories, and, for each failure condition in the
slice's hidden file, a scenario that shows it does not happen. It reads only the epic, its
stories and the hidden file. It never runs the eval: the eval runs later, after the build,
with no agent, through the usage guide. An eval is a fixed yardstick: a later run never changes
a scenario that is there.

The eval is written to be exact. Every step is a sentence of the step library of the slice's
surface kind (`standards/schemas/eval/steps-<kind>.yaml`), which a runner does with no agent;
every Then is an exact result a tester can see; there is no score — the eval passes only when
every scenario of every story passes. What only the build will make is a name, which the usage
guide maps later. The product owner sees a short summary, never the eval.

**Pipeline position: both.** start-change opens the change at the head (on the plan's
sub-branch); the end sequence commit-change → propose-change → check-change → merge-change
lands it.

## Role

You are the orchestrator. You own the step order, the summary and the checkpoint. The play
reads no memory itself. `template-manager` hands out the two eval templates, the step
libraries, the approval prompt and the close templates. The `evals-engineer` agent checks that
the copies are complete and calls the skill `author-slice-eval`, which writes every scenario;
the agent passes the skill's drafts on as they are and never writes content. You run all
mechanical work through bundled scripts: the gather and the copies (`gather_eval.py`), the
input check (`check_inputs.py`), the placing and the yardstick (`place_eval.py`), the eval file
check (`check_eval.py`), the summary (`render_summary.py`), the checkpoint record and the commit
gate (`record_approval.py`), the write guard (`scoped_write_guard.py`) and the stop condition.
The shared reader is `eval_common.py`. The play never writes an eval file by hand, and never
runs one.

**Forbidden:** reading an ICE page, the usage guide, the code or the product model, or handing
the agent anything but the copies (C1); writing outside the slices' eval files (C2); a story file
that is not Gherkin, whose `Feature:` is not its story, or a Then that is not exact; a score
(C3); a step that tests from the inside (C4); a goal, expectation or failure condition with no
scenario and no Untestable line, or a scenario that covers something no story or hidden-file
entry says (C5); a recovery or handoff text in the eval (C6); changing or deleting a scenario
that was there (C7); an eval for a slice that is not ready, or a slice not named (C8); a commit
before the typed yes, a checkpoint skipped by config, the eval itself shown in place of the
summary, or a stop that leaves a file (C9); landing outside the change plays or on the wrong
branch (C10); a real person's name, or text a person cannot follow (C11); a step that is not a
sentence of the surface kind's step library, or an eval run by an agent (C12); a guessed address
or command in place of a name, or a name not listed (C13); no time limit, or a story that is not
in the slice (C14).

**Agent boundaries:**

| Agent | Domain | Skills it uses | Phases |
|-------|--------|----------------|--------|
| `evals-engineer` | Check the copies are complete (each story copy has a Scope of work; the hidden-file copy has an entry for each story's feature; the step library of the surface kind and the two templates are there), call the skill, pass its drafts on as they are | `author-slice-eval` | Draft |
| `template-manager` (utility) | Hand out the eval templates, the step libraries, the approval prompt and the close templates (evidence file, delivery report, Next-line map) into short-term memory | — | Gather, Checkpoint, Close |

`evals-engineer` is the single **domain agent**; `template-manager` is the one utility agent.
The skill `author-slice-eval` was built for this play. The start and end sequence are injected
sub-plays; everything else is a script.

## Recovery

| For | Trigger | Direction | Handoff |
|-----|---------|-----------|---------|
| F1 | the run read an ICE page, the usage guide, the code, or any file other than the epic, its stories and the hidden file | throw away what was made from the wrong input, and make it again from the copies only | autonomous |
| F2 | an eval was written outside the slice's evals folder, or the run wrote another file outside its own records | undo each write outside the slice's eval files (`scoped_write_guard.py --restore`) | autonomous |
| F3 | a story file is not Gherkin a tool can read, its `Feature:` is not its story, a Then is not exact, or the slice file does not list every story in build order | write the story file again as Gherkin with its story as its `Feature:` and an exact Then, or write the slice file's list again in build order | autonomous |
| F4 | a goal, an expectation or a failure condition has no scenario and no Untestable line | add the missing scenario, or the Untestable line with its reason | autonomous |
| F5 | a scenario covers nothing a story or the hidden file says, or tests from the inside | take the scenario out, or write it again from the outside, on the surface | autonomous |
| F6 | the eval holds handoff text or a recovery | take out the handoff text or the recovery | autonomous |
| F7 | a later run changed or deleted a scenario that was there | put back each scenario that was there, word for word, and add only what is new | autonomous |
| F8 | a slice with no epic, stories or hidden file got an eval, or the run did not name it | take back the eval of the slice that is not ready, and name it in the summary with its reason | autonomous |
| F9 | a commit before the yes, or a stop that left a file | take the commit back, or undo the writes the stop left (`place_eval.py --undo`); show the summary again | human |
| F10 | the change landed outside the change plays, or on the wrong branch | land the change through the change plays, on the plan's branch | human |
| F11 | a page names a real person, or a person cannot follow it | rewrite with personas and plain words | autonomous |
| F12 | a step is not a sentence of the step library of the slice's surface kind, or a slice with no library got an eval | write the step again with a library sentence; when the surface kind has no library, take back its eval and name it | autonomous |
| F13 | a step holds a guessed address, command or field in place of a name, or a name is not listed | put a name in place of the guess, and list each name in the slice file | autonomous |
| F14 | the slice file has no time limit, or the eval covers a story that is not in its slice | set the time limit in the slice file, and take out the story that is not in the slice | autonomous |

## Pause and Resume

Steps run top to bottom. On entry, resolve the change issue from start-change's result, check the
status marker, skip completed steps, reset an in-progress step to pending, and continue. Nothing
is committed before Step 8. A resume after Step 4 started reads `place.json`: Step 4 undoes it
before it places again, so a file is never placed twice. A run that closed HALTED at a stop has
nothing to resume: its files were undone.
