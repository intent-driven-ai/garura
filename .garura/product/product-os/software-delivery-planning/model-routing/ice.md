## Intent
- Goal: Each Garura part runs on the right model and effort for its job, for speed and token cost, on each coding tool that takes one: its maker names a default tier and effort in its source by a written rule for its kind, and a project may change a part's tier in its settings; a step whose model a setting names runs on that model, apart from the session's, and a checker never on the session's own; each run records the model, effort, time and cost of each part; a person moves a part up or down a tier on that record, and an eval checks each move before it lands; and a router that chooses at run time comes only once the records show it pays.
- Limit: A part names a tier, never a coding tool's model id; carrying the tier into each coding tool stays with Install and distribute, which never chooses one.
- Limit: A checker step never runs on the session's own model.
- Limit: No move of a part's tier lands without an eval that passed on the new tier.
- Limit: No run-time router is built before the records of runs show it pays.
- Limit: A value a run cannot get is left empty in its record, never made up.
- Fails if: A part runs on a tier that neither its project's settings nor its source names, or names a tier its written rule does not give and says no reason.
- Fails if: A checker step runs on the session's own model, or a step runs on a model other than the one its setting names.
- Fails if: A part's tier moved with no record of its runs behind the move, or with no eval, or with a failed one.
- Fails if: A run's record misses a part it ran, or holds a model, effort, time or cost the run did not have.

## Context
- Read: Gather it from the memory layer. Look first at the project's existing memory and its existing implementation, then Garura memory, then Phoenix memory. If none of them answers, research it and raise a memory update for a person to approve. For this part, look for: each part's `model:` and `effort:` lines in its source; the written rule for tiers; the project's settings, among them each loop's checker, the page judge and the test model; the install's fold of tiers and what each coding tool takes as a model and an effort, as approved in memory; the records of runs: a play's evidence file with its session stamp, the loop's check record and the rebuild eval's record; the evals that can check a part; and Phoenix memory's page on choosing a model for each step.
- Never read: any memory file by its path, and any ICE page.
- Persona: the product owner, who pays for each run in tokens and waits for it; and the technical lead or the developer, who builds a part and names its tier and effort.
- Scope: In: the written rule for each part's tier and effort, each part's default in its source, a project's own tier in its settings, which steps run on a model a setting names and which models and services they may be sent to, the record of each part's model, effort, time and cost, moving a part on that record with an eval, and a run-time router once the records show it pays. Out: carrying the tier into each coding tool and laying the parts, keeping each setting in the settings file, the rest of each kind's written standard and its linter, where a run's records live, reading a step's setting and running the step, and the evals a play holds.

## Expectation
- Scenario: In a bank's payments service, a developer writes a skill that only formats reports, names `haiku` by the rule, and the team's loop checks its result on `sonnet` while the session runs on a larger model. A month of run records shows the sub-agent that reviews each change costs most and needs its strength, while a drafting skill on `opus` writes only short notes; the technical lead moves the skill to `sonnet`, its eval passes on `sonnet`, and the next install lays the new tier. In a law firm's contract review, the records show a run-time router would save little, and none is built.
- Done means: Someone other than the one who built the parts reads each part's source, the project's settings, the loop's check record, the run records, the move's record with its eval, and the laid parts, and finds every part on the tier its rule, its project or a checked move gave it; the bank's check made on `sonnet`, not the session's model; the moved skill on `sonnet` with a passed eval and the runs it rests on named; every value in the run records one the runs had; and no router in the law firm.
