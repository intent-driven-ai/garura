## Intent
- Goal: Once the work is built, a part that is not its builder tests it for security, at rest and while it runs in the testing environment, against the product profile's security level, its pass bar and each capability's security need, so that every part of the pass bar has a pass or a fail and the verdict is a pass only when every part passes; each finding goes back as a handoff plan to the developer when the builder can fix it alone, or to the product owner when a person must decide; and the tests run again as the product changes and when the security level goes up.
- Limit: The pass bar, its numbers and any standard it names come only from the product profile and each capability's security need; nothing that was not tested counts as a pass, and no finding is skipped, switched off or let through, nor a test loosened, to reach a pass.
- Limit: The builder never gets the security tests, their results or the verdict, only the handoff plan, which names the weakness, where it is and the way back, never the test, its rule, its id or its tool.
- Limit: Nothing is tested outside the testing environment, in production or on a builder's own machine; no record holds a secret's value; the records of the review of each change and of the build's separate test run are taken as evidence and not run again; and nothing comes from what the AI agent knows by itself.
- Fails if: The verdict is a pass while a part of the pass bar or a capability's security need failed or was not measured, or while a test could not run.
- Fails if: A test touched production, a builder's own machine or a system the testing environment does not hold, or a finding, the verdict, a handoff plan or a log holds a secret's value.
- Fails if: The builder was given a security test, its results or the verdict, or a finding that needs a person's judgment or authority went to the developer.

## Context
- Read: Gather it from the memory layer. Look first at the project's existing memory and its existing implementation, then Garura memory, then Phoenix memory. If none of them answers, research it and raise a memory update for a person to approve. For this part, look for: the product profile's security level, its pass bar and its compliance needs, each capability's security need in the product model, the security tools and settings the project's code already names, the architecture and the deployment design with where secrets are kept and which tests run where, the testing environment's declaration, the records of the review of each change and of the build's separate test run, the decisions that moved the security level, the earlier security verdicts, and the project's setting for rounds.

- Persona: the product owner, who set the security level, reads the verdict and decides each finding a person must decide; the developer gets back, as a handoff plan, each finding the builder can fix alone.

Out: the review of each change with its security rules, the tests inside the code, a story's own security lines, the other kinds of testing, setting or moving the security level, the deployment design and the environments, fixing, recording defects and running the plan, and landing the change.

## Expectation
- Scenario: A shop's checkout is built, and its profile sets security at high, with a pass bar that names a security standard and allows no serious finding. The test of the code finds a library with a known weakness, of which a version without it exists, and a payment provider's key written in a settings file; the test of the running build, in the testing environment, finds that a signed-in test buyer can open another test buyer's order. The product owner sees a verdict with those three fails. The developer gets two handoff plans: move the library to a version without the weakness, and let each buyer see only their own orders. The key goes to the product owner, because it must be changed where it is kept; the verdict names the file and never the key. After the fixes, the tests run again and pass.
- Done means: Someone other than the one who ran the tests runs them again on the same built work, gets the same verdict, and finds every part of the pass bar and each capability's security need with a pass, a fail or a reason it was not tested, no untested part counted as a pass, no secret's value in any record, no test outside the testing environment, and each finding sent where its way back says.
