## Intent
- Goal: Any team, in its own repository, builds and changes its plays and loops only through their ICE, with the same builders, and builds its sub-agents and skills to the written standard for their kind, so that every part it adds works as Garura's own do: each compiled play or loop records the fingerprint of its ICE, carries the shared scripts unchanged, points to the shared close and the shared loop run, declares each gate with its class and its way past, writes a record while it runs, and passes the linters.
- Limit: An intent change to a play or a loop goes through its ICE; only wording with no change in meaning is edited directly.
- Limit: A fingerprint is computed from the ICE, never made up.
- Limit: A shared script is copied unchanged; the shared close and the shared loop run are pointed to, never copied.
- Limit: No play is built without at least one constraint, one failure condition and one success scenario, and a loop does no work of its own.
- Limit: Skills and sub-agents carry no ICE; they follow the written standard for their kind and are checked against it.
- Fails if: A compiled play or loop says something its ICE does not, or its fingerprint does not match its ICE.
- Fails if: A shared script in a built part differs from its source, or a built part holds a copy of the shared close or the shared loop run.
- Fails if: A part is called built while the play linter or the loop linter reports a gap in it.
- Fails if: A team with Garura installed in its own repository cannot build or change a play or a loop there without Garura's source folders.

## Context
- Read: Gather it from the memory layer. Look first at the project's existing memory and its existing implementation, then Garura memory, then Phoenix memory. If none of them answers, research it and raise a memory update for a person to approve. For this part, look for: the play's or loop's ICE source and its compiled file, the builders and their references (the shared scripts, the compiled examples, the workflow shapes and the agent audit), the written standard for each kind of part, the loop principles, the gate rule, the successor map, the loop and gate settings, the kind of install the repository has and where its parts live, and the architecture pages for a team building a harness once they are written.
- Never read: any memory file by its path, and any ICE page.
- Persona: the technical lead or the developer of any team, who builds and changes the team's own plays, loops, sub-agents and skills in its own repository; and the product owner, who approves each play's and loop's ICE.
- Scope: In: building a play or a loop from its ICE and changing it through its ICE, the linters run on them, adding a gate and pinning or unpinning it, and building a harness in a team's own repository; and, not built yet, checking the loop principles, the run marker, and building a sub-agent and a skill to the standard. Out: the written standards, the naming rule and the play checker's rules, where each part lives, the settings, the memory tiers, the model each part runs on, running loops, the way past each gate, recording ADRs, laying parts in a project, and landing each change.

## Expectation
- Scenario: In a bank's own repository, with Garura installed and no Garura source folders, the technical lead builds a play that checks each payment change against the bank's rules. The builder asks for its constraints and failure conditions, generates its scenarios and one recovery for each failure, copies the shared scripts unchanged, points to the shared close, declares its pinned checkpoint, records the fingerprint and runs the play linter until it passes. A week later the developer adds a failure condition through /edit-play, and only the new eval and recovery change. In a game studio's harness repository the same month, a developer builds a loop of three plays; it holds only its own values and a pointer to the shared run, and the loop linter passes.
- Done means: Someone other than the one who built the parts reads the bank's play and the studio's loop with their ICE, and finds each fingerprint equal to the sha256 of its ICE, every shared script the same byte for byte as its source, no copy of the shared close or loop run, the checkpoint declared with its class, both linters passing, and, between the two versions of the play, changes only where the new failure condition reaches.
