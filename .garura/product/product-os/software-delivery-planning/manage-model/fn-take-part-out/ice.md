## Intent
- Goal: A part leaves the model only on a person's named approval and once no page still names it: parts are repointed from an old intent or the old one is dropped, an intent page goes once nothing names it, a capability merges into another with its features, links, intents and decisions, and a slice goes with its record, each all or nothing with every file put back on a failure; and, once built, a feature, a domain, an ICE and a capability with its own ICE page can be taken out the same way.
- Limit: No take-out without the name of the person who approved it.
- Limit: The skill writes no page words; the lines that name a part are changed first, through the page skill.
- Limit: A merged capability's needs are listed for a person, never copied, and nothing under the plans folder is touched.
- Fails if: A part is taken out with no person's name, or while a page or an entry still names it.
- Fails if: A failed take-out leaves any file changed, or the removed id is left anywhere in the index.
- Fails if: A merge loses a feature, a link, an intent or a decision of the merged capability.

## Context
- Read: Gather it from the memory layer. Look first at the project's existing memory and its existing implementation, then Garura memory, then Phoenix memory. If none of them answers, research it and raise a memory update for a person to approve. For this part, look for: the person's approval and their name, the request's repoints and removals, the index and every page that names a part being removed, the skill's request shape and refusals, what a merge moves, and the kinds the script cannot remove today.
- Never read: any memory file by its path, any ICE page, and any file in a plan's evals folder.
- Persona: the product owner, who approves each take-out; and the technical lead, who asks for a merge or a removal.
- Scope: In: repointing, removing an intent page, merging a capability, removing a slice, and, not built, removing a feature, a domain or an ICE and merging a capability with its own ICE page. Out: deciding that an intent is replaced or retired, choosing which duplicate to keep, fixing the words that name a part, and deleting a plan.

## Expectation
- Scenario: In a shop's checkout service, the product owner approves merging Wishlist into Saved items; a page still names Wishlist, so the first run writes nothing and names the line; once the page skill fixes it, the merge moves Wishlist's features, links, intents and decisions, removes its page and lists its needs for review. In a clinic's booking app, a request to remove a slice comes with no approver's name and writes nothing.
- Done means: Someone other than the one who asked reads the index, the pages and the reports, and finds the shop's first run with no file changed and the line named, the second with the approver's name, every feature, link, intent and decision of Wishlist on Saved items, Wishlist named nowhere, and its needs listed; and the clinic's slice still in the index.
