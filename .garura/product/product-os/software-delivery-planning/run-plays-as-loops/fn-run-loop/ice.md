## Intent
- Goal: Every loop runs the same steps from one written run: a pre-flight before anything is opened, one issue and one branch for the whole loop, its own questions and documents first with where each came from, one contract for every play, its source read once, and its plays in rounds, each play's done check proved by this run and its run files committed on a clean tree, each round decided as done, again (only the plays given work, on that work) or ask, up to the round limit; then the checker, the change landed with the person's yes on the merge, the evidence recorded, and a halted run picked up from the first play not done.
- Limit: Nothing is opened when the pre-flight fails, and no play runs before the loop's own questions and documents are in.
- Limit: The loop reads no memory itself, does no play's work, and hands no play another play's output as its input.
- Limit: No play inside the loop opens an issue, a branch or a pull request, and no pinned checkpoint is put off by the contract.
- Limit: A play's done check counts only when this run wrote it and it reads held, and the next play never starts on files left changed outside the issue.
- Fails if: A loop or a play writes outside the loop's issue, or a second issue or branch is opened.
- Fails if: A play runs before the loop's questions are answered, or an answer or a document has no recorded source.
- Fails if: A round goes on after a play missed its done check or left the tree unclean, or the loop runs past its round limit without asking.

## Context
- Read: Gather it from the memory layer. Look first at the project's existing memory and its existing implementation, then Garura memory, then Phoenix memory. If none of them answers, research it and raise a memory update for a person to approve. For this part, look for: the loop's own values, the Shared Loop Run and its scripts, the loop contract rule, the loop's settings (runner, round limit and evidence), the installed plays and whether each checks a loop contract, the person's answers and their sources, each play's done check, the round records with their gaps and open questions, and the run folder of a halted run.
- Never read: any memory file by its path, and any ICE page.
- Persona: the product owner, who gives a loop its goal, answers its questions first and gives the merge their yes; and the developer, a person or an AI agent who builds the code, who starts a loop and runs it again after a halt.
- Scope: In: the pre-flight, opening the change, the questions and documents first, the loop contract, reading the source once, the plays in rounds with their done checks and commits, the decision after each round, the end and close, and picking up a halted run. Out: the checker, the knowledge step and the brief, the status file, starting a loop from a schedule or a hook, running plays side by side, each loop's plays, the link rules, the review and the merge, building loops and their settings.

## Expectation
- Scenario: In a clinic's booking app, the product owner runs the Discovery loop on a working prototype. The pre-flight finds every play installed, the loop opens one issue and one branch, asks where the prototype is and how it starts, and gets the write-up. Round one runs its three plays in turn, each proving its done check; the step after the round leaves two capabilities with no features, so round two runs only the play that writes them, on those two. Round two leaves nothing open, so the loop goes to its checker and then lands its change on the yes. In a team's planning tool, a loop halts when its second play misses its done check; run again, it starts from that play and keeps the first play's work.
- Done means: Someone other than the one who ran the loop reads the run's records and the git log, and finds for the clinic one issue and one branch with every run file under that issue, the answers and the write-up recorded before the contract with their sources, a done check reading held for each play that ran, a round record reading again with only the one play and its two targets named, then one reading done, and the evidence record; and for the planning tool a halt naming the second play, and a second run that did not run the first play again.
