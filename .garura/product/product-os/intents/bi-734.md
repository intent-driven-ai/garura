# Garura publishes a standard for building agentic harnesses

**Outcome:** a written standard — how a harness is built, why it is built that way, and how its parts are named — that Garura follows everywhere and that clients can take and use for their own harnesses.

**Why:** Garura's names grew in four shapes (`vision`, `understand`, `fix-bug`, `play-creator`), verbs meant two things, and a planned play clashed with a skill (`manage-plan`). A harness clients adopt needs one rule they can learn once. People will mostly run loops, so loop names matter most.

**Asked by:** the product owner

**Proof it is met:** the standard is published; the component linter enforces it; every play, skill and loop in Garura passes the linter; an install leaves no old name behind in a project.

**Must not:** use a name that is, or starts with, a Claude Code or Codex built-in command; shorten words.

**Identified by:** #717 — naming the plan plays showed there was no standard.

**Plan:** this issue's number is the plan's ID — `.garura/project/plans/734.yaml`. Tracking only: a business intent holds no ICE.
