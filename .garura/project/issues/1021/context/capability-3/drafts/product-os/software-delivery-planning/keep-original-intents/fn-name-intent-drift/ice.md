## Intent
- Goal: Every place where an intent and the product no longer agree is named to a person.
- Limit: It never changes, confirms or drops an intent; it only names the drift.
- Fails if: An intent drifts from the product and nothing names it.

## Context
- Read: Gather it from the memory layer. Look first at the project's existing memory and its existing implementation, then Garura memory, then Phoenix memory. If none of them answers, research it and raise a memory update for a person to approve. For this part, look for: the intent pages and their stages, the model's index, each intent's issue in the tracker, and the rules for what must agree once the model is aligned.
- Persona: the product owner, who decides what to do about each drift.
- Scope: In: naming drift that has an intent in it. Out: making the missing links, drift with no intent in it, and sorting new input against the intents that exist.

## Expectation
- Scenario: A capability is linked to an intent in the index only, and the check names the intent, the capability and the missing side.
- Done means: Plant a known drift in a copy of the model, and a check run by someone other than its author names it.
