#893 An agent cannot do a play's work without the play: guardrails laid by the Garura install (OPEN)

> **Business intent** — reported by the product owner, 2026-10-26. Not attached to a plan yet; not shaped yet (no slice, no plan). To be added to Garura.

## What is wanted

An agent that runs Garura cannot do a play's work without the play. Today nothing stops it: an agent can run a play's bundled scripts by hand, write a play's record files itself, edit a compiled play or its ICE without `/edit-play`, or finish a failed step by hand and go on. The product owner, 2026-10-26, after it happened on #879 and #875: "did you use the plays? or just started to execute the work?" … "yeah dont take shortcuts. and we need to put in guardrails that these shortcuts are not taken" … "record that issue - as a feature we will add to garura - the hooks i mean".

The guardrails are laid by the Garura install, so every project that uses Garura gets them, not only Garura's own repo.

## The design proposed (to shape, not decided)

1. **A run marker.** Each play writes a "this play is running" record when it starts and clears it at its close, so there is a record that the play itself ran.
2. **A hook that blocks the shortcut.** A Claude Code hook (a script Claude Code runs before each tool call) refuses:
   - an edit to a play's compiled file or its ICE, the ontology, or an ADR, unless the matching play's run marker is present (`/edit-play`, `/edit-ontology`, `/record-decision`);
   - a commit on a plan's base branch or on main;
   - a run of a play's bundled script when no run marker for that play exists.
3. **A review check.** `/check-change` refuses a pull request when a commit that changed a play, the ontology or an ADR has no matching play run on record.

## Not decided

- Which paths and which plays the hook covers, and how a person overrides it on purpose.
- Where the hook's source lives in `core/components/` and how the install lays it and its settings.
- Whether the run marker is a new part of every play (through the play compiler) or one shared block the plays point to, like the Standard Play Close.

## Where it came from

- #879 was first opened by running `/start-change`'s scripts by hand, and its ICE was edited without `/edit-play` loaded; both were thrown away and redone through the plays.
- In #875's `/shape-plan 788` run, the start-change record was written by hand and the approval-prompt frame was skipped; earlier plays skipped the close's template load.
- A failed branch step (a git lock) was chained into a commit on `plan/788/base`.
