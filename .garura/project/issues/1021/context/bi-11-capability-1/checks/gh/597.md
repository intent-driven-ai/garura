# Rebuild the product model as an ontology

## Problem

The product model (`.garura/product/product-os/`) is a tree of domain → capability → functionality, with slices, epics, and per-slice lens files. It stores what Garura has written, not a proper model of what the product *is*. ADR 028 left one question open on this account: where the project-wide design outputs (UX, tech architecture, agentic, quality, run, marketing) live, now that design happens once per project and not per slice.

## Boundary

- In: rebuild the product model as an **ontology** — the kinds of things a product is made of, how they relate, and what each must hold — so that intents, shape, and design all have a defined home.
- Out: building loop recipes; changing plays beyond what the new model forces.

## Done when

- The ontology is written down and agreed.
- It answers where project-wide design outputs live (ADR 028, open question 3), and ADR 028 is updated with the answer.
- The plays that read and write the product model have a path to the new model.
