# Plays read the whole model by one rule once its index has ICE entries, so older parts break

## What is broken

The product model's index got its first ICE entries under #1021 (the reorganisation of the business intents): 13 parts of "Specify the product" now keep their ICE on its own page. The other parts, about 45, still keep it inside their page. Several scripts switch the whole model to the new rule as soon as the index has an ICE list, so every older part is now read wrongly. Each break below was confirmed on a copy of the model.

1. **The ready check calls every older part not ready.** Once the ICE list exists, `check_ice_workable.py` reads only ICE entries, so a part with its ICE inside its page "has no ICE". With the list: 0 ready, 13 partly ready, 45 not ready. Without it: 22 ready, 29 partly ready, 7 not ready. /shape-plan would skip every older feature. /update-plan drafts a story from the person's words instead of from the ICE.
2. **The plan helpers cannot find an older part's ICE.** `plan_common.py` (`ice_page`, `ice_lines`) returns nothing for a part with no ICE entry, so the plan plays refuse it even when the ready check passes.
3. **/update-plan cannot land a feature found during work.** The page skill writes the thin ICE on its own page, then the index skill is asked to mark the feature's page, which has no ICE section, so it refuses. The page files stay on disk with no index entry. If the new shape is sent instead, the index accepts it, but `check_agreement.py` still looks for the old marks. By then the story is already in GitHub.
4. **/shape-slice's model check fails on the slice that exists.** For older thin parts, `slice_check.py` looks for the mark on an ICE entry that is not there: 7 "thin mark drift" problems on the slice that serves bi-788, and the fix loop cannot clear them. `write_hidden_file.py` finds no "Fails if" lines for the older features, where it found 6 or 7 before.

Not affected: the grounding linter (it only adds warnings), `render_brief.py`, `remove_part.py`, `link_part.py` and /shape-eval's scripts.

## Why it matters now

/shape-plan and /update-plan should not run until the Agent-work tool (#1023) lands, so nothing has failed in use yet. But the next run of any of these plays on this model will hit these breaks.

## Fix direction

Read each part by its own shape, not the whole model by one rule. A part with an ICE entry is read from its ICE page, and a part without one from the ICE section inside its page. This holds until #765 moves the rest. The fix is to be shown to the product owner before it is built.
