# The current ontology and other current standards are in no memory tier

**What happens:** the current ontology (version 11, with the Slice kind) is in no memory tier. Its source is `core/components/memory/standards/schemas/product-os/ontology.md`, and config names it as `product.ontology: standards/schemas/product-os/ontology.md`. A memory-tool lookup finds only Phoenix memory's copy, which is version 4. Garura memory in this repo does not hold it.

The same gap holds for other current standards. Phoenix memory differs from Garura's source in about 100 files (it was last promoted only for the review rules, #860), and Garura memory holds only 26 files. Example: Phoenix has the old grounding template `functionality.md`, not `feature.md`. A part that reads a standard through the memory tool can get an old version, or none.

**Seen on:** /shape-slice 788 re-run (#866), Step 2.

## Expected
Every standard a play's agents read through the memory tool is reachable at its current version: in Garura memory for this project, or in Phoenix memory.

## Done when
A check lists each standard the installed parts name (the config's memory keys, the agents' "what you put in short-term memory" globs) and shows the memory tool answers it at the same content as Garura's source.
