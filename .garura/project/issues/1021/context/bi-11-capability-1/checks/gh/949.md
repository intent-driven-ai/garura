# Phoenix memory has fallen behind Garura's source in 60 places, so every project's agents read older rules

> Parent: #921 (Phoenix memory stays up to date as Garura is built). Found while promoting #929 (the pages #920 corrected), 2026-10-28. Not fixed in #929, which promoted only its own pages.

## The problem in plain words

Every project's agents decide from Phoenix memory. Phoenix memory is seeded from Garura's source (`core/components/memory/`), but many pages were changed in the source and never sent on. So agents in every project read older rules than the ones Garura now follows.

After #929 (Phoenix commit `dfdafe6`), Phoenix memory and the source still disagree in 60 places:

- **43 pages differ.** For example the ontology (`standards/schemas/product-os/ontology.md`), the slice and spine schemas, the lens schemas, `self-review.md`, `run-status.md`, and 18 knowledge pages. Most look like the source's renames (ADR 046) and newer rules; each needs checking for which side is newer.
- **3 pages exist only in the source:** `standards/rules/play-orchestration.md`, `play-patterns.md`, `user-questions.md`. Phoenix's own rules index already lists them, so a lookup that follows the index finds nothing.
- **14 exist only in Phoenix:** `standards/rules/architecture.md`, `design.md`, `epics.md`, `feature-catalog.md`, `features.md`, `kb-extension.md`, `product.md`, `scenarios.md`; `standards/schemas/intent-epic.yaml`, `mvp-recommendation.yaml`, `screen-inventory.yaml`, `product-os/grounding/functionality.md`; `standards/templates/feature-tree-output.md`; the `knowledge/work-intelligence/` folder. Some look retired in the source (#434 removed Intent Epics; Functionality became Feature). Others may have been added in Phoenix on purpose (`work-intelligence`).

## Fix

1. For each page, find which side is newer, and why a page exists on one side only. Do not delete a Phoenix-only page before knowing why it is there.
2. Promote what the source has newer, as one reviewed promotion.
3. Bring back into the source any page Phoenix has newer or on purpose.
4. Add a check that lists these differences, so drift is seen at each release (#921).

## Impact if not done

Agents in every project decide from out-of-date rules and schemas, and a rule Garura relies on (for example `user-questions.md`) cannot be found at all.
