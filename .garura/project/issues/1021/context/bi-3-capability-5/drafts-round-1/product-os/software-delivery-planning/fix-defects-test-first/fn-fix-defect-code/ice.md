## Intent
- Goal: Once every test that proves the defect has failed on the check's record, the builder changes the code from the cause and the fix design, in the order it chooses, until the record of a separate check, which runs the tests through a tool on the model or service the test model setting names, shows every test for the fix and every test the project already had passing; then it tidies the code it changed without changing what it does, with every test still passing and no test file changed, all without ever seeing a test.
- Limit: The builder is never handed a test, a test file, an eval, the hidden file or the evals folder, never writes or changes a test, and learns from the check only which results still fail.
- Limit: The builder changes only the files the fix design names, or writes why and sends the reason to the technical lead; the tidy stays inside the code the fix changed; and when a result still fails after the tries the project allows, the builder stops and the fix goes back.
- Limit: The check is never the builder; it changes no code and no test, takes each test file's fingerprint at its first run and its last, and a pass counts only on its record, never on the builder's word.
- Fails if: The builder was handed or read a test, a test file, an eval or the evals folder, or a test changed, was weakened or went away between the check's first run and its last.
- Fails if: The defect is called fixed while the check's record shows a test failing, or with no check run after the tidy.
- Fails if: A file outside the fix design changed with no reason, or the tidy changed what the code does or code the fix did not change.

Its cause: the limit check lets a transfer through only when it is below the limit, where a transfer up to the limit is meant, and the fix design names that one function. The project's test model setting sends the tests to a different model from the one that fixes the code, and a tool runs them. The builder is handed the cause and the fix design, and no test. It changes the comparison, asks the check, and the check's record shows all three tests for the fix and the project's earlier tests passing. The refusal message read the old rule, so the builder changes the message file too and writes why, and the reason goes to the technical lead. It then joins two lines that read the limit the same way, and the check's record shows every test still passing and every test file the same as at the first run. The fix session's record shows no read of a test file or the evals folder.
- Done means: Someone other than the builder compares what the builder was handed and the fix session's record with the check's records, and finds no test, eval or evals folder handed or read, every test passing on the last record, every fingerprint the same as at the first run, and each file outside the fix design with its reason.
