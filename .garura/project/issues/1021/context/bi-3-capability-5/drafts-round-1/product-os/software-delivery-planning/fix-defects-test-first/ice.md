## Intent
- Goal: Every bug handed on by Gather the work under a chosen plan item is fixed test first: an AI agent traces its cause and designs its fix, the technical lead confirms or changes both, a test writer who is not the builder writes the code-level tests that prove the defect and a separate check shows each one fails before any fix code, then the builder fixes the code from the cause and the fix design, without seeing a test, until the check finds every test passing, and tidies the code it changed while every test stays passing.
- Limit: The builder is never given a test, a test file, an eval, the hidden file or the evals folder, never writes or changes a test, and learns from the check only which results still fail.
- Limit: The cause and the fix come from the project's code and memory first, then Garura memory, then Phoenix memory, or from research only after a person approves it as a memory update; the fix changes only the files the fix design names, or says why; and nothing changes a work item, the plan file or a status.
- Limit: A pass counts only on the record of the separate check, which runs the tests through a tool on the model or service the test model setting names, apart from the model that fixes the code, never on the builder's word.
- Fails if: Fix code was written before every test that proves the defect failed on the check's record, or the cause only restates the bug's own words.
- Fails if: The builder read or was handed a test, an eval or the evals folder, or a test changed, was weakened or went away between the check's first run and its last.
- Fails if: The defect is called fixed while a test for it, or a test the project already had that passed before the fix, fails on the check's record.

## Expectation
- Scenario: In a shop's checkout, a bug sits under the story that brought it in: a guest's total is wrong when the same discount code is entered twice. The technical lead names the bug by its ID. An AI agent traces it to the function that adds discounts, which adds a code again each time it is entered, and designs the fix: keep one of each code, with the other way, refusing the second entry on the page, weighed and set aside because the mobile app sends codes too. The technical lead confirms both. A test writer, on the model the project's test model setting names, writes two tests from the bug and its cause, and the check shows both fail. The builder, handed the cause and the fix design and no test, changes the function, and the check finds both tests and the project's earlier tests passing. The builder joins two lines that read the codes the same way, and the check finds every test still passing and no test file changed.
- Done means: Someone other than the builder compares the check's records with the tests, and finds each test failed before any fix code, passed after the fix and after the tidy, no test file different between the first run and the last, and every test the project already had still passing.
- Done means: Someone other than the AI agent that traced the defect reads the cause against the code and the bug, and finds the file, the logic and why it is wrong, not the bug's own words, with the technical lead's confirmation on record.
