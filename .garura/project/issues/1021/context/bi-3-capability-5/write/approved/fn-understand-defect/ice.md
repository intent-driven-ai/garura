## Intent
- Goal: From a defect reported anywhere, the developer who will write its tests finds the feature of the product model that the defect breaks, the tests the project already has for that behaviour and why they pass while the defect is there, and the root cause, the file, the logic and why it is wrong, and writes only what the fix needs, in a builder's part that names no test and a test writer's part; a defect that no feature covers is named as a new need for Specify the product and not fixed.
- Limit: The understanding comes from the report, the product model, and the project's code, history, tests and memory first, then Garura memory, then Phoenix memory; a point none of them answers stays open with a memory update raised for a person to approve, and nothing comes from what the AI agent knows by itself.
- Limit: It writes no design document, no steps for the builder and no test, and changes no code, test, work item, plan file or status.
- Limit: The one who understands the defect is never its builder; when the project's setting asks for it, no fix code is written before the technical lead's yes; and a second defect found on the way is named for a person to report, not fixed.
- Fails if: A defect goes on to be fixed with no feature of the product model named, or a defect that no feature covers is fixed instead of named as a new need.
- Fails if: The cause repeats the report's words or names no file and no logic, or a test that exists for the behaviour is left out or has no reason why it passes.
- Fails if: The builder's part names a test or why one passes, or a design document or a list of steps was written.

## Context
- Read: Gather it from the memory layer. Look first at the project's existing memory and its existing implementation, then Garura memory, then Phoenix memory. If none of them answers, research it and raise a memory update for a person to approve. For this part, look for: the defect report as it was given, the product model's features and capabilities, for a bug in a plan the plan file and the story it sits under, the project's code and its history, the tests it already has and how they run, the project's setting for the technical lead's yes, and the ontology's rules for a feature, a story and a bug.
- Never read: the plan's evals folder, the eval, the slice's hidden file and any ICE page.
- Persona: the developer who understands the defect and then writes its tests, a person or an AI agent who is never the builder of the same fix; the technical lead agrees the fix when the project's setting asks for it.
- Scope: In: reading the report, matching it to a feature, finding the tests that exist and why they pass, the root cause, what the fix changes, naming a new need, and the technical lead's yes when it is asked for. Out: recording the defect, specifying a new need, adding a part the model is missing, the tests that prove the defect, the fix code, and designing the work.

## Expectation
- Scenario: In a library's loans service, a member writes that a book cannot be renewed on the day before it is due. The developer who will write the tests reads the report and finds the feature in the product model, Renew a loan, in the loans capability. It finds three tests for renewals, and the check shows all three pass: none tries a renewal one day before the due date. It traces the cause to the function that counts the days left, which counts the due day itself, and names the one file the fix changes, in one line. The builder's part holds the feature, the cause and that line, and no test. The same week a member asks for a reminder by text message before a book is due; no feature covers it, so it is named as a new need for Specify the product, with the member's words, and not fixed. No code changed and no design document was written.
- Done means: Someone other than the developer who understood the defect reads the understanding against the product model, the code and the tests, and finds the feature named, each test that exists with why it passes, a cause with the file, the logic and why it is wrong, no design document and no steps, and no test in the builder's part.
