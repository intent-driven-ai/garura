## Intent
- Goal: A team gets Garura installed in the shape of whichever coding tool it works in, among Claude Code, Codex, GitHub Copilot, Antigravity and Factory: that tool's own adapter, behind the one install engine, lays each chosen part that the tool can run where the tool reads it, with the shared files, the memory guide, Garura's instructions and the guardrails in the tool's own form and the tier each part names carried into the tool's own setting; each tool's state is named, and a tool that cannot yet run what would be laid gets a plain message and no install.
- Limit: The engine names no coding tool in its own steps; each tool's shape is laid only by that tool's adapter, so adding a tool never changes the engine.
- Limit: No part is laid in a tool without what it needs to run there; a tool that is stopped, removed or not built stops with a plain message and writes nothing.
- Limit: No file of the team's own in its tool's places, such as its instructions file or its tool's settings, is written over, and nothing is written outside the project's folder and the machine's own Garura folders without the person's yes.
- Limit: Only the tier a part already names is carried; which model and effort each part runs on is not chosen here.
- Fails if: A tool named as built lays a part that does not load in that tool, or that points to a file the install did not lay, or the check of the installed layout fails on that tool's folders.
- Fails if: Adding or changing a tool changes a step of the engine, or the engine's steps name a tool.
- Fails if: An install for a stopped, removed or unbuilt tool writes anything, or a file of the team's own changed, or a file was written outside the project and Garura's own folders, with no yes on record.

## Context
- Read: Gather it from the memory layer. Look first at the project's existing memory and its existing implementation, then Garura memory, then Phoenix memory. If none of them answers, research it and raise a memory update for a person to approve. For this part, look for: the coding tool the team works in; what that tool loads from a project (its instructions file, its folders for sub-agents and skills, its commands, hooks and settings, and where a model can be named), as approved in memory; the adapter for that tool and its state; the parts of the chosen kind with the tier each names; the files the team already has in its tool's places; and the guardrails Orchestration defines.
- Never read: any memory file by its path, and any ICE page.
- Persona: the product owner, who brings Garura into the project whichever coding tool the team works in.
- Scope: In: laying each part in each tool's shape through its adapter, on an install and an upgrade; which tools get an install and each tool's state; the shared files, the memory guide, Garura's instructions and the guardrails in each tool's form; carrying each part's tier. Out: the engine's own steps, the record, the kinds, the check and the take-out; moving to a new version; the set-up after the install; which model each part runs on; what the parts are and how they are built; the naming rule; what each guardrail guards.

## Expectation
- Scenario: Three teams install Garura on the same day. A shop's checkout team works in Claude Code: every sub-agent and skill is laid where Claude Code reads it, its own instructions file stays as it was, and every part loads. A bank's payments team works in Codex: the install stops with a plain message that names the redesign, and nothing in its project changed. A clinic's booking team works in a tool with no adapter: the install refuses the tool by name before it writes anything.
- Done means: Someone other than the one who ran the installs compares each project before and after, finds for the built tool every part where the tool reads it and loading, the check of the installed layout passed, the team's own files unchanged and nothing written outside the project and Garura's own folders; finds for the stopped tool and for the tool with no adapter nothing written and a plain message; and finds that the engine's steps were the same for every tool.
