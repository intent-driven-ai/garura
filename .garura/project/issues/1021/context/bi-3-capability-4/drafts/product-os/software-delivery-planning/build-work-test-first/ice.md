## Intent
- Goal: Every story, chore and spike under the item the technical lead names is built test first: all the code-level tests for the work are written by a test writer who is not the builder and shown to fail by a separate check before any code, then the builder writes all the code from the design and its own part, without seeing a test, until the check finds every test passing, then the code is tidied while every test stays passing, and the build delivers the slice's usage guide.
- Limit: The builder is never given a test, the test writer's part, an eval, the hidden file or the evals folder, never writes or changes a test, and learns from the check only which expected results still fail; the test writer never sees the builder's code, an eval or the hidden file.
- Limit: The build follows the design, the project's code and its standards and changes none of them; a departure from the design goes back to the technical lead with its reason; and what the build follows comes from the project's code and memory first, then Garura memory, then Phoenix memory, or from research only after a person approves it as a memory update.
- Limit: A pass counts only on the record of the separate check, which runs the tests through a tool on the model or service the test model setting names, apart from the model that builds the code, never on the builder's word; and the build changes no work item, plan file or status.
- Fails if: Code for the work was written before every test for it was written and shown to fail, or a test that passed, or was never run, before the code is counted.
- Fails if: The builder read or was handed a test, the test writer's part or the evals folder, or a test changed, was weakened or went away between the check's first run and its last.
- Fails if: The work is called built while a test for it, or a test the project already had that passed before the build, fails on the check's record, or the tests were written or run on another model or service than the test model setting names.

## Expectation
- Scenario: The technical lead of a clinic's booking product names the epic of a slice on a browser page, with two stories. The project's test model setting sends the writing and the running of the tests to a different model from the one that builds the code, and a tool runs them. The test writer writes seven tests from the two stories' expectations and the booking service the design names, and the check shows all seven fail because the service is not built. The builder, handed the design and its own part and no test, builds the service and the booking page; the check tells it one expected result still fails, the builder finishes it, and the check finds all seven and the project's earlier tests passing. The builder joins two repeated functions into one, the check finds every test still passing and no test file changed, and the builder writes the slice's usage guide. The build session's record shows no read of a test or the evals folder.
- Done means: Someone other than the builder compares the check's records with the tests for the work, and finds every test failed before any code, passed after the build and after the tidy, no test file different between the first run and the last, and every test the project already had still passing.
- Done means: Someone other than the builder reads what the builder was handed and the build session's record, and finds no test, test writer's part, eval, hidden file or evals folder in either.
