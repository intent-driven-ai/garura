# Where what is owed is kept

- Atlassian: keep technical debt in the same backlog as new features, because teams lose product-wide priorities when it is kept apart; mark it with an issue type, or with custom fields and labels that share one workflow. https://www.atlassian.com/blog/jira/3-steps-taming-technical-debt
- GitHub push protection: 'I'll fix it later' becomes an open alert in the repository's security list, which stays until someone closes it. https://docs.github.com/en/code-security/concepts/secret-security/about-push-protection
- Azure Policy: each exemption is its own record beside the resource; the compliance report shows the resource as Exempt; an expired exemption is kept for the record; Microsoft advises revisiting exemptions regularly. https://learn.microsoft.com/en-us/azure/governance/policy/concepts/exemption-structure

What they share: one list that both a person and a later step read, in the place the normal work is read; each entry names what was skipped, who skipped it, when and why; an entry is closed only when the debt is paid.
