Thin: proposed from the person's words; deepen with `/discover-capabilities`.

## Intent
- Goal: The project's technology is set once for the whole project: each language, framework, data store and outside platform it is built with is a position with its version, its reasons, its source and the person who confirmed it.
- Limit: Each proposal names its source, the project's code first and then memory, and a choice that nothing backs stays open, with no default.
- Limit: Only a person confirms a position, and no work waits for one.
- Fails if: A position is written with no source, or with no person's confirmation.
- Fails if: A position contradicts the technology the project's code already uses, and no change of position explains it.
- Fails if: Work stops because a technology position is missing.

## Context
- Read: Gather it from the memory layer. Look first at the project's existing memory and its existing implementation, then Garura memory, then Phoenix memory. If none of them answers, research it and raise a memory update for a person to approve. For this part, look for: the project's code and its settings, the product profile with its shape and quality levels, the technology learnings in memory with the conditions each fits, and the positions already set.
- Persona: the architect, who confirms each technology position.
- Scope: In: proposing and setting the technology positions for the whole project. Out: the shape of the system, changing a confirmed position, the platform the product runs on and its environments, the product profile, the memory the project gets, and each slice's own design.

## Expectation
- Scenario: In a project whose code is written in Java, the language is proposed as Java with the files that show it, and the architect confirms it.
- Done means: Someone other than the one who set them reads the technology positions and finds, for each, its version, its reasons, its source and the person who confirmed it, and finds each open choice named.
