## Intent
- Goal: After a loop's run, the product owner reads in Argus, the one review tool, what the run made, as business intents with their ICE, the product, the ADRs, memory with its waiting updates, and the agent decisions with their traces, and answers each piece in the page or one card at a time; every answer is kept on the run's branch as it is given, a piece sent back comes back reworked, and at Finish the review step applies every answer in one commit, so that the agents build only from what a person approved and the person never reads a raw file to know what was made.
- Limit: Only a person answers a piece, one at a time, by the rules of the part that owns its kind: an intent is confirmed only by a person, a memory update follows Memory's rules and an ADR follows Manage ADRs; a swipe never changes a piece.
- Limit: Argus writes nothing to the model, holds no Garura code and reads no Garura path; Garura and Argus meet only through the written contract, and no agent reads the review's web page.
- Limit: A send-back reworks only the piece sent back, landing the change stays with Ship every change the same way, and production is never touched.
- Fails if: A piece was answered by an agent, in bulk, or changed by a swipe with no typed answer.
- Fails if: An answer the person gave is missing from the run's branch or from the one commit, or the commit holds a change the person did not choose.
- Fails if: Argus holds or imports Garura code, or the person had to open a file to judge a piece.

## Context
- Read: Gather it from the memory layer. Look first at the project's existing memory and its existing implementation, then Garura memory, then Phoenix memory. If none of them answers, research it and raise a memory update for a person to approve. For this part, look for: the run's branch against where it lands; the plays' review records in the loop's review folder; the model's pages and its index, with each piece's approval state once it is kept; the ADRs that wait; the memory updates that wait and the decision records with their traces; the address Argus is reached at, and its contract's version.
- Never read: any memory file by its path, any ICE page, the review's web page, and production.
- Persona: the product owner, who reviews what a run made and gives the answers only a person may give.
- Scope: In: opening a review on what a run changed, reading it in the five sections, answering each piece in the page or one card at a time, the answers on ADRs, memory updates and agent decisions, sending a piece back to be reworked, applying the answers in one commit, and Argus as a Phoenix tool behind its contract. Out: landing the change, reviewing it against its standards, the approval state on each piece and how it is kept, the rules of memory updates and of ADRs, running a loop, writing each kind of piece, and the findings and recommendations of Run → Product.

## Expectation
- Scenario: A loop's run on a shop's checkout drafts two business intents with their ICE, a capability with three features, one ADR, one memory update on how long a guest cart is kept, and twelve agent decisions. Argus opens on the whole model's state, then shows what the run changed. On a phone, the product owner swipes right on one intent and its ICE, sends the capability back with the comment "guest checkout must not need an account", drops one feature, approves the memory update in his own words, and accepts the ADR. The capability comes back reworked with a reply, and he accepts it. He presses Finish: one commit on the run's branch marks what he accepted as approved, removes the dropped feature, writes the memory update to the issue's short-term memory, and accepts the ADR, and the change goes on to land with the merge waiting for his yes.
- Done means: Someone other than the one who built the review compares each answer given in Argus with the events kept on the run's branch and with the one commit, and finds every answer there once, no piece changed without a typed answer, no answer given by an agent, nothing written by Argus to the model, and no Garura code in Argus.
