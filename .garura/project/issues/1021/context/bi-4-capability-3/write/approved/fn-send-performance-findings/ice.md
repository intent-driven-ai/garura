## Intent
- Goal: Once the running build is measured, one performance verdict for the built work gives each part of the profile's pass bar and each capability's performance need a pass or a fail with the conditions it was measured in, names each part not measured with its reason, is a pass only when every part passes, and says so plainly when no performance level is set; and each finding goes back as a handoff plan with what is slow, where, in what conditions and the way back: to the developer through Build the work test first when the builder can fix it alone, to the product owner when a person must decide, and to Fix defects test first when the work was already accepted.
- Limit: The verdict takes the records of the review of each change and of the build's separate test run as evidence without running them again, and it is kept where no part that builds the work reads it.
- Limit: A handoff plan never names the test, its rule, its id or its tool, never gives the figures measured, and its way back is guidance, never code.
- Limit: A finding goes to the developer only when its way back is a change of the code the builder controls; one that changes the architecture, the deployment design or an environment, one not measured because the environment cannot give its conditions, the level itself, or one in doubt goes to the product owner, and only an approved decision moves the performance level.
- Fails if: The verdict is a pass while a part failed or was not measured, or a missing performance level is read as a pass.
- Fails if: A handoff plan names the test, its rule, its id or its tool, or gives the figures measured, or the builder was given the verdict.
- Fails if: A finding that needs a person's judgment or authority, such as more copies of a service, went to the developer, or a finding was let through with neither a fix nor an approved decision.

## Context
- Read: Gather it from the memory layer. Look first at the project's existing memory and its existing implementation, then Garura memory, then Phoenix memory. If none of them answers, research it and raise a memory update for a person to approve. For this part, look for: the figures, passes, fails and conditions of the two measuring features and each part they did not measure, the product profile's performance level and pass bar, each capability's performance need, the decisions that moved them, the records of the review of each change and of the build's separate test run, the approved architecture, the deployment design and the environments' declarations, whether the work was already accepted, and the recovery rule.
- Never read: the value of any secret, such as a password or a key; anything in production, such as its data or its traffic; and any ICE page.
- Persona: the product owner, who reads the verdict and decides each finding a person must decide; the developer gets back, as a handoff plan, each finding the builder can fix alone.
- Scope: In: the one verdict against the profile's performance level, and writing and sending each handoff plan. Out: measuring the running build, fixing, changing an environment, setting or moving the performance level, recording a defect in the tracker, and running the tests again.

## Expectation
- Scenario: A clinic's booking endpoint that another system calls is measured. The verdict fails two parts of the pass bar and names a third, the answer time under the named number of requests each second, as not measured, because the environment for load tests is declared too small to carry it. The developer gets a handoff plan: the endpoint that lists free slots is slower than the level allows for a clinic with many doctors, because it asks the data store once for each doctor; ask once for all of them. The product owner gets the second finding, which needs more copies of the booking service, and the part not measured, each with its conditions. No handoff plan names a test, a tool or a figure.
- Done means: Someone other than the one who gave the verdict reads it beside the figures and the pass bar, and finds every part with a pass, a fail or a reason it was not measured, each with its conditions, no pass while a part failed or was not measured, each handoff plan with what is slow, where and the way back, sent where the recovery rule's test says, and no test or figure named in any of them.
