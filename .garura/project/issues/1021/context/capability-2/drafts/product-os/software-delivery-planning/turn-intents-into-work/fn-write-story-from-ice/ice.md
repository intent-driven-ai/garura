## Intent
- Goal: Each story carries every line of its feature's ICE and its capability's ICE except the "Fails if" lines, in its own words, so an agent can act on it without asking again.
- Limit: The writer reads only the clean copies, never an ICE page.
- Limit: The Context guidance says where to look, never the facts.
- Fails if: A story holds a line of a "Fails if" block, the words "Fails if" or a recovery phrase.
- Fails if: A story lacks its goals, its limits, its expectations or one of the four Context lines.

## Context
- Read: Gather it from the memory layer. Look first at the project's existing memory and its existing implementation, then Garura memory, then Phoenix memory. If none of them answers, research it and raise a memory update for a person to approve. For this part, look for: the clean copies of the two ICE, the slice's name and outcome, and the Story kind in the ontology.
- Never read: an ICE page, the slice's hidden file and the folder that holds the evals.
- Persona: the agent that builds the story.
- Scope: In: a story's title, scope of work and Context guidance. Out: which stories exist, filing them, the hidden file and the ICE itself.

## Expectation
- Scenario: A feature with a ready ICE gets a story whose limits come from its ICE's limits, and whose text holds no "Fails if" line.
- Done means: The draft check, which reads the original ICE pages and not the writer's copies, reads ok for every story.
