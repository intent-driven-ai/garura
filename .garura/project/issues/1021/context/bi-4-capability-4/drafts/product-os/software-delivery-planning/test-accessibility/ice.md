## Intent
- Goal: Once the work is built and runs in the testing environment, tools run by a part that is not its builder, and a person who is not its builder walking the slice with a keyboard alone and with a screen reader, test it on each declared surface a person opens against the product profile's accessibility level, its pass bar, each capability's accessibility need and each surface's accessibility guideline, so that every part has a pass or a fail with how it was checked and the verdict is a pass only when every part passes; each finding goes back as a handoff plan to the developer when the builder can fix it alone, or to the product owner when a person must decide; and the tests run again as the product changes, when the accessibility level goes up and when a surface's accessibility guideline is updated.
- Limit: What is tested, and whether a tool or a person checks it, come only from the product profile, each capability's accessibility need and each surface's accessibility guideline, with the profile's level as the floor; nothing that no tool checked and no person walked counts as a pass, and a tool's clean run never passes a part a person must check.
- Limit: The builder never gets the accessibility tests, their results, the walks or the verdict, and never walks its own work; only the handoff plan reaches it, and it names what a person cannot do, where and the way back, never the test, its rule, its id or its tool.
- Limit: Nothing is tested outside the testing environment, in production or on a builder's own machine; the records of the review of each change and of the build's separate test run are taken as evidence and not run again; and nothing comes from what the AI agent knows by itself.
- Fails if: The verdict is a pass while a part of the pass bar, a capability's accessibility need or a surface's accessibility guideline failed, was not tested, or was a part a person must check that no person walked.
- Fails if: A test or a walk touched production, a builder's own machine or a system the testing environment does not hold, or the builder walked its own work.
- Fails if: The builder was given an accessibility test, its results, a walk's record or the verdict, or a finding that needs a person's judgment or authority went to the developer.

## Expectation
- Scenario: A clinic's booking page is built, and its profile sets accessibility at high with a pass bar that names a standard and says a tool and a person's walk check it; the browser surface's accessibility guideline asks for the same and for every step to work with a keyboard alone. In the testing environment the tools find each field labelled and each text clear against its background. The person the product owner named walks the booking end to end: with a keyboard alone, the dialog that confirms the visit cannot be left; with a screen reader, each free slot is read out only as a button with no time. The product owner sees a verdict with those two parts failed, each with how it was checked. The developer gets two handoff plans: a patient using a keyboard alone cannot leave the confirmation dialog, so the keyboard must be able to close it; and a patient using a screen reader cannot tell the free slots apart, so each must say its time. No test, tool or rule is named. After the fix, the tools run and the person walks again, and both pass.
- Done means: Someone other than the one who ran the tests and the one who walked runs the tools again and walks the same steps on the same built work, gets the same verdict, and finds every part of the pass bar, each capability's accessibility need and each surface's accessibility guideline with a pass, a fail or a reason it was not tested, each walk naming who walked and how, no part a person must check counted as passed by a tool, no test outside the testing environment, and each finding sent where its way back says.
