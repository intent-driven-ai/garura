## Intent
- Goal: How the whole project runs is designed once, with the approved architecture turned into a physical architecture of services, container platform and cloud, the path through the environments Environment setup declares, ending at pre-production, with its pipeline for continuous integration and continuous delivery and the tests in each environment, how a release goes live and is rolled back, where secrets and settings are kept, and the cost on each cloud, each part with its reason, its source and the person who confirmed it.
- Limit: Each part is proposed from the project's own memory and code first, then from the cloud cartridges and Garura memory, then from Phoenix memory; only when none of them answers is it researched, and the research is used only after a person approves it as a memory update. Nothing comes from what the AI agent knows by itself.
- Limit: The path runs through the environments Environment setup declares, each built and managed on its own from one reused design and only when a deployment to it is needed, and ends at pre-production; nothing here touches production; every part of the architecture gets a place to run; and the design never holds the value of a secret.
- Limit: Only a person confirms a part and chooses the cloud, and no work waits for either.
- Fails if: A part of the design is set with no person's confirmation, or with nothing behind it but what the AI agent knows by itself.
- Fails if: Anything in the design, its pipeline or a deploy it plans touches production.
- Fails if: An agent that prepares a release cannot find in the design where a part runs, which tests it must pass or how it is taken back, and decides it alone with no gap named.

## Context
- Read: Gather it from the memory layer. Look first at the project's existing memory and its existing implementation, then Garura memory, then Phoenix memory. If none of them answers, research it and raise a memory update for a person to approve. For this part, look for: the project's code and its settings, such as its container files, its Kubernetes files, its pipeline files, its deploy scripts, its infrastructure files and its hosting settings; the approved architecture, with its parts and their technology, and the declared surfaces; the quality levels and the compliance needs in the product profile; the cartridge of each cloud; Phoenix memory's architecture and technology learnings for running, testing and releasing a product, with the conditions each fits; and the project's set-up answers, when it has them.
- Never read: the value of any secret, such as a password or a key.
- Persona: the devops engineer, who confirms how the project runs, is tested and is released, and chooses the cloud.
- Scope: In: proposing and setting how the whole project runs: the physical architecture, the path through the environments Environment setup declares and the one design each is built from, the pipeline for continuous integration and continuous delivery, the tests in each environment, release and rollback, stored data, secrets and settings, the cost on each cloud and the rules every release keeps. Out: updating the design, preparing the cartridges, setting up each environment, production, the architecture and its technology, carrying out the pipeline, writing and running the tests, the files that carry out the design, the product profile, and moving a memory update into Phoenix memory.

## Expectation
- Scenario: A team's planning tool, one deployable unit with a database and a browser page, gets its physical architecture proposed from its container file: one container service and a managed database. Mapped onto each cloud's cartridge, its cost is shown on AWS, GCP and Azure for one team, a wider trial and the whole company, in the same form. The path runs through dev, where each change runs with the rest, testing, where the slice's tests run, and pre-production, where a check shows the page answers, and it stops there. The devops engineer chooses a cloud and confirms the design.
- Done means: An agent that did not make the design prepares a release to testing from the design alone, naming the services, the container platform, the cloud, the path, the tests, the way back and where the secrets are kept, and a person other than the one who made the design finds a source and a confirmation behind each part, the three costs side by side, and no step that reaches production.
