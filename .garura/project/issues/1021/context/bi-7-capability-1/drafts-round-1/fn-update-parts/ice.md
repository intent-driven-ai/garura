## Intent
- Goal: When a team changes what its project gets, the install, run again through the same engine from either front door, shows what it will add and take out, then lays what is newly chosen and takes out what its record says Garura laid before and the new choice or the version no longer holds, keeping the project on its version, naming each part added and taken out, and keeping the new choice in the record, with nothing outside the record changed.
- Limit: Only parts the install record names are ever taken out, and only inside the project; a part or file of the project's own is never touched.
- Limit: The version stays as it is; moving to a new version, the parts Garura renamed and a person's edits to an installed part are Upgrade a project's.
- Limit: Nothing is taken out before the person has seen the list of what goes.
- Fails if: A part the record does not name, or a file outside the project, is changed or gone after the update.
- Fails if: A part the new choice leaves out, or one the version no longer has, is still in the project afterwards.
- Fails if: A part was taken out with no list shown first, or the report or the record does not match what changed.

## Context
- Read: Gather it from the memory layer. Look first at the project's existing memory and its existing implementation, then Garura memory, then Phoenix memory. If none of them answers, research it and raise a memory update for a person to approve. For this part, look for: the install record with the earlier choice and version, the new choice, the parts of the project's version with their workers, and the parts of the project's own beside Garura's.
- Never read: any memory file by its path, and any ICE page.
- Persona: the product owner, who changes what the project gets as the project's needs change.
- Scope: In: running the install again with a new choice, laying the parts newly chosen, taking out from the record what is no longer chosen or no longer in the version, and the report and record of it. Out: the first install, the kinds themselves, moving to a new version, the parts Garura renamed, keeping a person's edits, and taking all of Garura out.

## Expectation
- Scenario: A team that builds its own harness added the slice-shaping play by name for a test. A week later it runs a plain harness install. The list shows the play and its workers to go; after the yes they are gone, the report names each, the record holds the harness kind alone, and the team's own skill beside them is as it was.
- Done means: Someone other than the one who ran it compares the project and the record before and after, and finds every part added or taken out named in the report, nothing outside the old record changed, and the list shown before the first part went.
