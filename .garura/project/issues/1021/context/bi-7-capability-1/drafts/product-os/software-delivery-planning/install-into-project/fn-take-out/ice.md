## Intent
- Goal: When a team takes Garura out of its project, the list of what goes and what stays is shown first, and on the person's yes exactly what the install record says Garura laid is removed, with the empty folders it leaves, while the team's work, its product model, its own files, Phoenix memory and, unless the person asks, the machine-wide copy of memory stay, so a team can try Garura knowing it can leave it.
- Limit: Only what the record names is removed, and only inside the project, save the machine-wide copy of memory when the person asks; the team's work and its product model are never removed.
- Limit: Nothing goes before the list is shown and the person says yes, and a file Garura laid that a person changed since goes only on the person's yes for that file.
- Limit: Phoenix memory is never removed.
- Fails if: After a take-out, a file of the team's work, its product model or one of its own files is changed or gone.
- Fails if: Something went with no list shown first or no yes, or a file a person changed went without the person's yes for it.
- Fails if: A file or folder the record names is still in the project afterwards, other than those the person chose to keep.

## Context
- Read: Gather it from the memory layer. Look first at the project's existing memory and its existing implementation, then Garura memory, then Phoenix memory. If none of them answers, research it and raise a memory update for a person to approve. For this part, look for: the install record, the project's files as they are now and which of Garura's laid files a person changed since, the team's work and its product model, and where the machine-wide copy of memory and Phoenix memory sit.
- Never read: any memory file by its path, and any ICE page.
- Persona: the product owner, who decides to take Garura out and says yes to the list.
- Scope: In: the list shown first, removing what the record names, keeping the team's work, its product model and its own files, asking about each file a person changed, and the machine-wide copy of memory when asked. Out: changing the choice of parts, retiring the machine-wide copy of memory, and giving a record to a project that has none.

## Expectation
- Scenario: After a month, a team takes Garura out of its planning tool. The list shows each part, the memory tool, the tools and Garura's settings file to go, and the folders of work, the product model, the team's instructions file and its own two skills to stay. The settings file was edited to name the team's tracker, so the person is asked about it and keeps it. After the yes, the listed files are gone and the empty folders pruned, and Phoenix memory and the machine-wide copy are still on the machine.
- Done means: Someone other than the one who took it out compares the project before and after, and finds every file the record named gone save those the person chose to keep, every file of the team's work, its product model and its own files as before, and the list and the yes on record before the first file went.
